# Opencode Sandbox

A simple [qemu]-based sandbox for running your [opencode] agents. This project uses [microvm.nix]
under the hood for declarative VM management.

New sandboxes are configured using the [nix] programming language. This allows you to bundle in any
arbitrary dependency you might need for development with ease.

## Getting started

Simply add `opencode-sandbox` to your flake inputs:

```nix
{
  inputs.nixpkgs.url = "github:nixos/nixpkgs?ref=nixos-unstable";

  inputs.opencode-sandbox.url = "path:../../.";
  inputs.opencode-sandbox.inputs.nixpkgs.follows = "nixpkgs";

  outputs = {nixpkgs, opencode-sandbox, ...}: {
    # ...
  }
}
```

From there you can configure your own sandbox environments by overriding the `sandbox` package:

```nix
  outputs = {
    nixpkgs,
    opencode-sandbox,
    ...
  }: let
    system = "x86_64-linux";
    pkgs = nixpkgs.legacyPackages.${system};
  in {
    packages.${system} = rec {
      sandbox = opencode-sandbox.packages.${system}.sandbox.override {
        opencode-sandbox = {
          extraEnv = with pkgs; [nodejs prettier];
        };
      };
    };
  };

```

Check out the [opencode docs] for information on how to configure opencode. You can also find a few
self-contained examples under the `examples/` folder.

```bash
nix run ./examples/shared-env
```

## Implementation

Sandboxing works by having the host create a new throw-away `.sandbox` worktree in the current
working directory. This worktree is mounted into a shared volume in a qemu VM, leaving other files
untouched.

> [!CAUTION]
> **All files generated by the agent are cleared on exit**, including the worktree and sandbox
> branch itself!.

This kind of sandbox is mostly intended for parallel work, where you have a local agent work on some
small bug or feature while you hack away on some other branch.

All storage, including conversations, installed packages and code changes are not persisted between
runs, so make sure to have your agent push to remote once a feature is complete or a bug resolved.
From there you can inspect the diff and choose whether to merge the branch or not.

## Options

> _A list of all available options can be found under `module/options.nix`._

Options are specified using the `opencode-sandbox` override argument:

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    # Options go here...
  };
}
```

### `mem`

Amount of RAM made available to the sandbox in megabytes.

Setting the limit too low won't cause the sandbox to crash but might result in certain processes
being unexpectedly terminated.

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    mem = 8192;
  };
}
```

### `vcpu`

Number of virtual CPU cores made available to the sandbox.

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    vcpu = 4;
  };
}
```

### `storeSize`

Host storage reserved for the sandbox's nix store in megabytes.

Data stored here is not persisted and is wiped on shutdown and restart. Make sure to set a high
enough limit in accordance to your use case as nix evaluation will fail if the store is full.

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    storeSize = 32768;
  };
}
```

### `forwardPorts`

Ports to forward for sandbox-to-host communication.

This is mostly useful when exposing host services such as a local inference server which would be
too impractical to run inside of a sandboxed environment. Special care should be taken when using
this option not to expose any or privileged sensitive services.

> [!NOTE]
> See `examples/unsloth-desktop` for an example of how to use this to connect to a locally running
> unsloth instance.

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    forwardPorts = [8888];
  };
}
```

### `baseEnv`

Base packages which make up the agent's default set of tools.

When adding new tooling, it is preferable to edit `extraEnv` instead. Only edit `baseEnv` if you
wish to _remove_ certain tools which you do not want the agent to have access to.

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    baseEnv = with pkgs; [busybox git];
  };
}
```

### `extraEnv`

Extra packages which are used to augment the agent's available tooling.

Use this to add project-specific tooling. It is generally a good idea to have `extraEnv` match your
own development environment to make it easier for you to apply the agent's changes on the host.

> [!NOTE]
> See `examples/shared-env` for an example of how this can be done.

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    extraEnv = with pkgs; [nodejs prettier];
  };
}
```

### `opencode.package`

Opencode package in use inside of the sandbox.

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    opencode.package = pkgs.opencode;
  };
}
```

### `opencode.config`

Opencode configuration, either as a path to a file or as raw `json`/`jsonc`.

When set, the configuration is written to `opencode.jsonc` in the shared work directory before
opencode starts and removed again once it exits. Any pre-existing `opencode.jsonc` or
`opencode.json` is backed up first and restored afterwards, so user configurations are never
modified.

```nix
opencode-sandbox.packages.${system}.sandbox.override {
  opencode-sandbox = {
    opencode.config = ./opencode.jsonc;
  };
}
```
